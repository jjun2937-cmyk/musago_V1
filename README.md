# musago_V1 — 무사고전환 데이터/레이아웃 산출 자동화

무사고 전환 판매플랜 관련 계약 데이터에서, 조건별 계약 건수를 집계하는 엑셀 업무를
파이썬 스크립트로 재현 가능하게 만든 작업입니다.

이 저장소는 여러 차례 지표 정의를 다시 잡으며 반복 개발되었습니다 (아래 "버전
히스토리" 참고). **지금 실제로 쓸 것은 최종 버전(v4) 하나뿐**이며, 다음 섹션에
사용법이 있습니다. v1~v3는 그 이전까지의 개발 과정 기록으로 남겨둔 것입니다.

## 최종 버전 사용법 — `scripts/run_pipeline.py`

데이터 시트(수금부문명 헤더 보유)와 매핑정보 시트, 이렇게 2개 시트가 든 엑셀
파일 하나만 주면, 아래 3단계를 자동으로 실행해서 "데이터 파일"과 "결과 파일"을
만들어주는 통합 실행기입니다.

```bash
# 필요 패키지: pip install openpyxl
# 필요 프로그램: LibreOffice (soffice)
#   Ubuntu/Debian: sudo apt-get install libreoffice-calc
#   macOS:         brew install --cask libreoffice

python scripts/run_pipeline.py <입력.xlsx> <데이터출력.xlsx> <결과출력.xlsx>
```

내부적으로 하는 일:
1. **`build_report_v4.py`** — 입력 파일에서 데이터/매핑정보 시트를 자동 식별하고,
   필요한 컬럼을 헤더명으로 찾아(없으면 폴백 규칙 적용) 사고전환판매플랜코드·
   매핑정보 키값을 채운 뒤, 레이아웃 4종(당월/전체 × 부문별/상품별)을 수식으로 생성
2. **`recalc_util.py`** — LibreOffice headless로 전체 수식을 재계산 (openpyxl은
   계산된 값을 캐시하지 않으므로 필수 단계). 수식 오류가 있으면 셀 목록을 출력
3. **`split_report_v4.py`**(의 로직) — 원본 13만 행 데이터가 든 무거운 "데이터
   파일"과, 레이아웃 4종만 값으로 담은 가벼운 "결과 파일"로 분리해서 저장

옵션: `--timeout 초`(기본 600, 데이터가 많으면 늘릴 것), `--keep-combined`(중간
결합 파일을 안 지우고 남겨서 디버깅용으로 확인 가능)

### 지표 정의와 산출물 구조는 아래 "v4" 섹션에 자세히 정리되어 있습니다.

## 버전 히스토리

### v1 — `fill_data_sheet_formulas.py` / `fill_layout_formulas.py`

가장 처음 버전. 시트명/컬럼 위치가 고정된 하나의 실제 파일을 대상으로,
`업무정의` 시트에 적힌 규칙을 그대로 수식으로 구현했다.

```bash
python scripts/fill_data_sheet_formulas.py <원본.xlsx> <중간.xlsx>
python scripts/fill_layout_formulas.py <중간.xlsx> <최종.xlsx>
```

#### 데이터 시트 (T/W/X/Y/Z열)

| 열 | 정의 |
|---|---|
| T (사고전환판매플랜코드) | `최초판매플랜코드(K) & 무사고년수(S)`를 키값으로 매핑정보 시트 E열에서 찾아 F열 값을 반환 |
| W | 현재판매플랜코드(E) = 경과전환판매플랜코드(M) 여부 |
| X | 현재판매플랜코드(E) = 사고전환판매플랜코드(T) 여부 |
| Y | 경과년수(L) = 무사고년수(S) 여부 |
| Z | `V(사고구분코드)가 '01'/'02'가 아니고 Y=FALSE이면서 (X=TRUE 또는 W=TRUE)`이면 `'기전환'`, 아니면 공란 |

#### 결과레이아웃 시트 (개념상 A~I, 실제 시트열 B,C,D,E,F,G,H,I,K)

| 개념 | 실제열 | 정의 |
|---|---|---|
| A 전체계약건수 | B | 수금부문(개인/전략/신사업/법인)별 전체 계약 건수 |
| B 사고有 | C | V가 '01' 또는 '02'인 건수 |
| C = A-B | D | (기존 수식) |
| D 기존전환완료 | E | Z='기전환'인 건수 |
| E = C-D | F | (기존 수식) |
| F 기존미전환 | G | V not in(01,02), Z≠'기전환', Y=FALSE 인 건수 |
| G = E-F | H | (기존 수식) |
| H 전환완료 | I | V not in(01,02), Z≠'기전환', Y=TRUE, X=TRUE 인 건수 |
| I = G-H | K | (기존 수식) |
| 현장활동확인 (001~007) | O~U | "I"의 여집합(V not in(01,02), Z≠'기전환', Y=TRUE, X=FALSE) 중 전환처리구분코드별 건수 |

`결과레이아웃`에 이미 있던 D/F/H/K/J/L/N/M/V/W열 등의 수식은 그대로 두었고,
하드코딩된 0이 들어있던 B/C/E/G/I/O~U열에만 위 규칙대로 수식을 채웠습니다.

레이아웃에는 4개 월 블록(26.4월/23.5월/23.6월/23.7월)이 있는데, 데이터 시트가
단일 월(계약체결월 전부 '06') 자료라서 **첫 블록(6~9행)만** 이번 데이터로 채웠고
나머지 3개 블록은 대응하는 원본 데이터가 없어 건드리지 않았습니다.

#### 주의: 엑셀 COUNTIFS 조건문자열의 숫자/텍스트 오인 버그

V열(사고구분코드) 값 `'01'`/`'02'`, U열(전환처리구분코드) 값 `'001'`~`'007'`은
텍스트지만 숫자처럼 보이는 문자열입니다. `COUNTIFS(range, "<>01")`처럼 조건문자열로
비교하면 실제 Excel은 `01`을 숫자 `1`로 해석해버려서, 텍스트 셀은 숫자와 절대
같을 수 없으므로 `<>1` 조건이 모든 행에서 TRUE가 되어(필터가 무력화되어) 잘못된
값이 나옵니다. (재현/검증에 쓰는 LibreOffice는 텍스트로 올바르게 비교하기 때문에
처음에는 이 문제를 놓쳤습니다.)

그래서 V/U열과 비교하는 결과레이아웃의 **C, G, I, O~U열은 `COUNTIFS` 대신
`SUMPRODUCT` 배열비교**로 작성했습니다. `SUMPRODUCT` 안의 `=`/`<>`는 조건문자열
파서를 거치지 않고 셀 값을 있는 그대로 비교하므로 텍스트/숫자 오인 문제가 없습니다.

#### 검증

- 결과레이아웃의 모든 집계값을 원본 데이터에서 순수 파이썬으로 독립 재계산한
  값과 대조하여 일치함을 확인했습니다.
- LibreOffice 재계산 기준 수식 오류 0건 (단, 법인 그룹처럼 계약 건수가 0인 경우
  비율(%) 계산에서 발생하는 `#DIV/0!`는 손대지 않은 기존 비율 수식의 특성이며
  원본 템플릿에도 이미 존재하던 현상입니다).

### v2 — 헤더명 기반 범용 스크립트 (`scripts/build_report.py`)

시트명이나 컬럼 위치가 매번 달라지는 원본 파일에도 대응하도록 일반화한 버전입니다.
이후 데이터는 "데이터 시트"와 "매핑정보 시트" 두 개만 제공되며, `결과레이아웃`은
매번 새로 생성합니다.

```bash
python scripts/build_report.py <입력.xlsx(데이터+매핑정보 두 시트)> <출력.xlsx>
```

#### 동작 방식

1. **시트 자동 식별** — 시트명과 무관하게, 헤더에 `수금부문명`이 있는 시트를
   데이터 시트로, 나머지를 매핑정보 시트로 식별.
2. **헤더명으로 컬럼 탐색** — 컬럼 순서/개수가 달라져도 아래 헤더 텍스트로 위치를
   찾음: 현재판매플랜코드, 최초판매플랜코드, 경과전환판매플랜코드, 경과년수,
   무사고년수, 사고구분코드, 전환처리구분코드, 수금부문명, 계약체결월.
3. **헤더 폴백 규칙** — 위 세 플랜코드 헤더가 없으면:
   - 최초판매플랜코드 → `적용시작일시` 바로 오른쪽 `판매플랜코드` 열
   - 현재판매플랜코드 → `상품명` 바로 오른쪽 `판매플랜코드` 열
   - 경과전환판매플랜코드 → `세부플랜코드` 바로 오른쪽 `전환판매플랜코드` 열

   찾은 열의 헤더는 결과 파일에서 정식 이름으로 바꿔 씁니다.
4. **매핑정보 키값열 자동 생성** — `키값` 헤더가 없으면 새로 추가하고
   `=판매플랜코드&경과년수` 수식으로 채움.
5. **T/W/X/Y/Z 열** — 데이터 시트에 해당 헤더가 있으면 재사용, 없으면 맨 우측에
   새로 추가 (v1과 동일한 로직).
6. **결과레이아웃 동적 생성** — `계약체결월`의 고유값 개수만큼 월 블록을 만들고,
   각 블록은 `수금부문명`에 "개인/전략/신사업/법인" 키워드가 **포함**되는지로
   매칭(`SEARCH`, 대소문자 무관 부분일치)해서 4개 그룹 + 합계 행을 채움
   (예: `개인부문`, `개인사업부문` 모두 "개인" 그룹으로 매칭).
   **총계(합계) 행은 4개 그룹의 합이 아니라 해당 월 전체를 그룹 구분 없이
   독립적으로 재집계**합니다 — 그룹 키워드 어디에도 안 걸리는 수금부문명(예:
   `경영지원실`)이 있어도 총계에서 누락되지 않도록 하기 위함입니다(v2 초판에는
   총계=SUM(4개 그룹)으로 되어 있어 이런 행이 총계에서 빠지는 버그가 있었고,
   실사용 중 발견되어 수정했습니다). 각 블록에는 그룹 매칭에서 빠진 건수를 바로
   보여주는 **"미분류(그룹매칭 안됨)" 행**도 추가되어, 이 값이 0이 아니면 데이터에
   예상 못한 수금부문명이 있다는 뜻입니다.
7. **추천요약 시트 신규 추가** — 월×부문을 한 화면에 정리한 요약표
   (전체계약건수/전환대상/기전환완료/당월전환대상/전환완료/완료율(%)/전환미완료/
   현장활동확인/현장활동미확인), 완료율(%) 열에는 3색 조건부서식 적용.

#### v2로 실제 검증한 사례

(당시 파일명 `result/무사고전환_결과_04-07월.xlsx` — v4에서 파일 분리 방식으로
바뀌면서 이 파일은 지금 저장소에는 없고 아래 v4의 데이터/결과 파일로 대체됨)
시트명이 `Sheet1`/`Sheet2`였고, 데이터
컬럼이 42개(원본 26개 대비 증가)였으며 04~07월 4개월치(134,943행)가 섞여 있던
실제 데이터로 실행한 결과. 위 폴백 규칙이 모두 실제로 발동했고(현재판매플랜코드,
최초판매플랜코드, 경과전환판매플랜코드 헤더가 실제로 없었음), 수금부문명도
`개인사업부문/전략사업부문/신사업부문/법인사업부문`으로 되어 있어 포함-매칭이
실제로 필요했습니다. 06월 데이터에 그룹 키워드 어디에도 안 걸리는 `경영지원실`
1건이 있어 총계 행 버그(위 6번 항목)가 이 실행에서 실제로 드러났고, 수정 후
재검증했습니다. LibreOffice 재계산 기준 수식 오류 0건(679,683개 수식), 총계행
포함 독립 파이썬 재계산과 04~07월 전체(총계 4개 + 그룹 16개 + 미분류 4개) 완전
일치 확인.

**참고**: 이 결과를 검증할 때 이전 결과물인 `result/무사고전환_데이터_결과.xlsx`
(단일 월 데이터 기반)의 06월 값과 직접 비교해보려 했으나, 두 파일의 증권번호를
대조한 결과 **겹치는 계약이 0건**이었습니다(증권번호 대역 자체가 다름). 즉 두
파일은 같은 06월 데이터가 아니라 서로 다른 표본이라 값을 1:1로 대조하는 검증은
의미가 없고, 대신 각 파일 내에서 원본 데이터 → 순수 파이썬 재계산 → 시트 수식
값이 일치하는지로 검증했습니다.

### v4 — 지표 정의 재설계 + 데이터/결과 파일 분리 (`scripts/build_report_v4.py`)

v2의 T/W/X/Y/Z(경과년수=무사고년수 비교) 기반 지표를 폐기하고, "무사고전환은
사고구분코드가 아니라 실제 판매플랜코드로 역추적해야 한다"는 논의 끝에 아래
지표로 완전히 새로 설계했습니다.

#### 핵심 전제

- **무사고년수 필드는 실시간이 아니다.** 그래서 `경과년수 ≠ 무사고년수`로 보여도
  실제로는 같을 수 있고, 이 경우 판단은 코드 일치 여부로 역추적한다.
- 전환은 오직 무사고년수만큼만 가능하다 (별도의 "정상승급 트랙"은 없음).
- **사고구분코드('01'=당사사고 / '02'=타사사고)** 자체도 "이번 사이클"에만 찍히는
  값이라, 과거 사고 이력 전체를 대변하지 않는다 (경과년수>무사고년수인 계약의
  78%가 사고구분코드는 공백).

#### 지표 정의

| 항목 | 정의 |
|---|---|
| 유지계약(A) | 그룹별 전체 계약 건수 |
| 사고有(당사)(B) | 사고구분코드='01' **이면서** 현재판매플랜코드 ≠ 경과전환판매플랜코드 (01이어도 이미 경과전환판매플랜코드로 올라와 있으면 여기서 빠지고 당월전환완료로 편입) |
| 당월전환대상 | 유지계약 − 사고有(당사) |

#### 파일 분리

한 파일에 원본 데이터(13만 행)와 레이아웃을 같이 담으면 20MB가 넘어가서,
**데이터 파일**(데이터 시트 + 매핑정보, 수식 유지)과 **결과 파일**(레이아웃
4종만, 값으로 고정)을 분리했습니다. 레이아웃의 SUMPRODUCT 수식이 데이터 시트를
참조하기 때문에, 결과 파일에는 데이터 시트가 없어 수식을 그대로 옮기면 `#REF!`가
납니다. 그래서 순서를 이렇게 잡았습니다:

```bash
python scripts/build_report_v4.py <입력.xlsx> <결합.xlsx>      # 1) 결합 파일 생성(수식)
# LibreOffice로 결합 파일 재계산 (recalc_util.py 또는 엑셀에서 열기)
python scripts/split_report_v4.py <재계산된_결합.xlsx> <데이터.xlsx> <결과.xlsx>  # 2) 분리
```

지금은 이 두 단계 + 재계산을 `scripts/run_pipeline.py` 하나로 묶어서 실행하면
됩니다 (맨 위 "최종 버전 사용법" 참고).

- `result/무사고전환_데이터_04-07월.xlsx` — 데이터 파일 (약 20MB)
- `result/무사고전환_결과레이아웃_04-07월.xlsx` — 결과 파일 (약 35KB, 레이아웃 4종)
